# ADR-0005 — Git 저장소를 원본 템플릿에서 개인 계정으로 분리

- **상태**: 채택됨
- **날짜**: 2026-08-05

## 맥락

이 프로젝트는 `TOKTOKHAN-DEV/orca-ai-company` 템플릿을 clone해서 시작했습니다. `origin`이 그
템플릿 레포를 그대로 가리키고 있었기 때문에, 이 상태로 커밋을 쌓으면 "AI 빌더 그룹 랜딩 페이지"라는
구체적인 프로젝트의 이력이 범용 템플릿 레포의 이력과 섞이게 됩니다.

`project-docs/기획안_확정본_AI빌더그룹_랜딩페이지_v1.0.md`(§0-1)에서 대표님이 확정한 진행 방식도
"팀원 개개인이 처음부터 끝까지 단독 개발"하고 "각자 개인 계정으로 진행, 최종 산출물만 전달"하는
것입니다. 템플릿 레포에 직접 push하는 구조는 이 방식과 맞지 않습니다.

## 결정

`git remote set-url origin`으로 origin을 템플릿 레포(`TOKTOKHAN-DEV/orca-ai-company`)에서 개인
레포(`jspark054/ai-builder-group-landing`)로 교체했습니다. 이후 커밋은 모두 이 개인 레포에
push합니다.

## 근거

- **템플릿과 인스턴스의 분리** — 템플릿은 여러 프로젝트가 재사용할 범용 출발점이어야 합니다.
  특정 프로젝트(랜딩 페이지)의 콘텐츠·설정·커밋이 템플릿에 섞이면 다음 사용자가 템플릿을 다시 쓸 때
  이전 프로젝트의 흔적을 걷어내야 합니다.
- **개인 계정 진행 방침과의 일치** — 대표님이 확정한 운영 방식(각자 개인 계정, 최종 산출물만 전달)을
  그대로 반영합니다.
- **권한 사고 예방** — 템플릿 레포에 대한 쓰기 권한을 계속 들고 있으면 실수로 템플릿에 직접
  push할 위험이 있습니다. origin 자체를 바꿔서 이 경로를 원천적으로 차단합니다.

## 트레이드오프

- 템플릿 레포에서 이후 발생하는 개선(훅 수정, 스킬 추가 등)이 이 레포에 자동으로 반영되지 않습니다.
  필요하면 템플릿을 별도 remote(예: `upstream`)로 추가하고 수동으로 merge/cherry-pick해야 합니다.
- 템플릿과의 커밋 히스토리 연결점(fork 관계)이 GitHub 상에는 남지 않습니다. clone 기반 분리라
  GitHub이 이 레포를 fork로 인식하지 않습니다.

## 되돌리려면

`git remote set-url origin https://github.com/TOKTOKHAN-DEV/orca-ai-company.git`으로 origin을
되돌릴 수 있습니다. 단, 그 시점까지 개인 레포에 쌓인 프로젝트 전용 커밋(콘텐츠, ADR 등)이 템플릿
레포 이력에 그대로 섞이므로 권장하지 않습니다.
