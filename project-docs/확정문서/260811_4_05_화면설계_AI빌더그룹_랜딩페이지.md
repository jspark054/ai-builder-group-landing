## 1. 개요

### 1.1 목적

『화면 목록(IA)』(ABG-IA-002)과 『기능 명세』(ABG-FN-003)를 화면 단위로 시각화한다.
**요소의 배치 · 위계 · 표시 조건**을 정의하며, 색 · 타이포 · 간격은 디자인 시안 단계에서 정한다.

### 1.2 적용 범위

| 구분 | 수량 |
|---|:---:|
| 공개 화면 | **13** (P-12 · P-13 추가) |
| 관리 화면 | **7** (A-06 · A-07 추가) |
| 시스템 화면 | 2 |
| **합계** | **22** |

**『화면 목록(IA)』 v3.1의 22종과 일치한다.** 관리자 권한이 2단으로 확정되어(안건 1)
`A-06 빌더 개인 관리`가 v1.0의 18종에 추가됐고, v1.3에서 인사이트 3종(`P-12` · `P-13` · `A-07`)이 추가됐다 — 안건 2의 오독 정정에 따른 것이다.

### 1.3 참조 문서

| 문서 | 번호 | 관계 |
|---|---|---|
| 요구사항 정의서 | ABG-REQ-001 | 상위 |
| 화면 목록 (IA) | ABG-IA-002 | 상위 |
| 기능 명세 | ABG-FN-003 | **동급 — 충돌 시 기능 명세 우선** |
| 정책 정의 | ABG-POL-004 | 동급 |
| 결정시트 | — | 작업용 |

### 1.4 단일안 원칙

와이어프레임은 IA·기능의 시각화이므로 **2~3안으로 분기하지 않고 1종으로 합의한다.**
매뉴얼 §03이 *"확정된 화면 수가 범위 기준선"*이라 규정하므로 화면 수가 복수일 수 없다.

> REQ-C-010(주력 1~2안 + 비교 스토리)은 **디자인 시안**에 적용되는 요구이며 화면 설계는 대상이 아니다.

## 2. 결정 반영 현황

| ID | 결정 | 화면 영향 |
|---|---|---|
| A-1 | 관리자 + 빌더 **2단 권한**. 관리자 계정 복수, 실무 1인 | **A-06 신규** · A-01 · A-02 · A-03 |
| A-3 | 랜딩 **포트폴리오 우선** 배치 | P-01 섹션 4 |
| A-4 | 포트폴리오 **단일 목록** + 순서 배치 | P-03 |
| G-3 | 담당 빌더 **복수 (N:M)** | C-01 · P-04 · A-03 |
| G-3c | 카드 복수 표기 — `FN-C01-04`에 기정의 | C-01 |
| G-3d | 공동 프로젝트 **담당자 전원 페이지 노출** | P-05 · P-06 |

**A-3 결정 사유** — *"아직 빌더의 경력이 부족해 신뢰도 저하 우려"* (팀장 결정).
빌더 경력이 축적되면 재검토 가능한 판단이므로 근거를 기록한다.

## 4. 공통 컴포넌트

### 4.1 C-01 프로젝트 카드

사용 화면 — **P-01 · P-03 · P-06**. 화면별로 별도 카드를 구현하지 않는다.

```
┌─────────────────────────────────┐
│ ┌─────────────────────────────┐ │ ← 실제 화면 썸네일
│ │      실제 화면 썸네일         │ │   alt 필수
│ └─────────────────────────────┘ │   미등록 시 카드 제외
│ [교육] [예약]                   │ ← 분류 배지 · 최대 2개
│ ▓▓▓▓▓▓▓▓▓                       │ ← 프로젝트명
│ ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁            │ ← 요약 1~2줄
│                                 │
│ ○ 김OO 외 2명  [자세히][바로가기]│ ← 담당 빌더 · 이동
└─────────────────────────────────┘
```

| 항목 | 규칙 | 근거 |
|---|---|---|
| 담당 빌더 복수 | *"OOO 외 N명"* | FN-C01-04 |
| P-06에서 사용 | **담당 빌더 표기 생략** (해당 빌더의 페이지) | 03 §3.1 |
| 링크 등급 `none` | **바로가기만 미노출.** 콘텐츠·상세 진입은 유지 | POL-03 |
| 썸네일 미등록 | 등록 불가 처리. 카드 렌더 대상 제외 | POL-02 |

> **`FN-C01-06`(자세히 보기)은 삭제 불가 기능이다.** 이 링크가 없으면 P-04가 고아 페이지가 되어
> 색인되지 않으며 본문 500자 작성이 무효가 된다.

### 4.2 C-02 빌더 카드

사용 화면 — **P-01 · P-05**

```
┌────────┐ ┌────────┐ ┌────────┐
│   ●    │ │   ◐    │ │   ○    │  실사 / 아바타 / 폴백(이니셜)
│ 표기명  │ │ 표기명  │ │ 표기명  │
│ [1기]  │ │ [1기]  │ │ [2기]  │  ← 기수 배지
│ 3건    │ │ 1건    │ │ 5건    │  ← 담당 프로젝트 수
└────────┘ └────────┘ └────────┘
    세 유형이 섞여도 그리드 높이 유지
```

| 항목 | 규칙 |
|---|---|
| 표기 수위 혼재 | **정상 상태.** 실사·아바타·미등록이 섞여도 레이아웃 유지 |
| 프로젝트 수 | 공개 상태만 집계. **공동 담당 건 포함** (G-3d) |
| 프로젝트 0건 | 목록에 노출하지 않음 (POL-02) |

### 4.3 C-03 문의 CTA

사용 화면 — **P-01 · P-04 · P-06**. 위치별 문구가 다르다.

| 위치 | 문구 | 파라미터 |
|---|---|---|
| P-01 | 프로젝트 상담하기 | `utm_source=home` |
| P-04 | **비슷한 프로젝트 상담하기** *(v1.2 변경)* | `ref={project-slug}` · `utm_source=portfolio` |
| P-06 | 이 빌더의 경험으로 상담받기 | `builder={builder-slug}` · `utm_source=builder` |

**파라미터는 최소한 GTM이 읽어 GA4 이벤트에 싣는다.**

> ⚠️ **`REQ-C-002` 정정 대상** — 문서에는 *"플러그는 URL 파라미터를 수신하지 못한다(실측 확인)"*가
> **확정**으로 기록돼 있으나, **발주사가 "플러그에도 파라미터를 넣을 수 있다"고 확인했고
> 가이드 문서를 전달할 예정**이다. 리드 자체에 출처가 실리는지는 수령 후 확정한다 (안건 10).

> **섹션 2·3의 2행 구조 (v1.2 신설)** — 각 항목이 **발주자의 속마음을 인용부호로 먼저 보여주고(R1),
> 그 아래에서 소구점이 답하는(R3)** 형태다. 인용문은 시각적으로 답보다 약하게(작게·연하게) 두어
> 답이 주목받게 한다. 인용이 답보다 강해지면 페이지가 불안을 파는 인상이 되므로 POL-13의
> 공포 마케팅 금지에 저촉된다.
>
> 이 구조 때문에 **섹션 3은 기존 카드 3개 나열이 아니라 3쌍의 문답 블록**이 된다. 카드 컴포넌트를
> 반복하지 않게 되므로 POL-11 ②-6(동일 카드 컴포넌트 반복) 완화에도 기여한다.
>
> 카피 후보(기획-2안)는 『기능 명세』 §4.1 기획-2안 카피 표 참조 — 기획-1안(시안1 원문)은
> 카피 전략 보고서 §11. 둘 다 확정이 아니다 (결정시트 `I-7`).

> **섹션 5의 선택 기준** — `FN-P01-06`은 *"일부만 표시한다"*까지만 정의하고 **무엇을 고르는지는 없다.**

- **권한 판정은 서버에서 한다.** 프론트 은닉으로 대체하지 않는다 (REQ-N-011)

**관리자 계정은 복수이나 실무 담당자는 1인이다.**
승인 워크플로를 여러 관리자에게 분산하지 않고, POL-08 체크리스트를 한 사람이 통과시킨다.

### 6.4 A-06 빌더 개인 관리 `/admin/my` — 신규

**A-1 확정으로 추가된 화면이다.**

```
┌──────┬───────────────────────────────────────────┐
│ 내   │ ▓▓▓ 내 프로필      로그인: 김OO (builder)  │
│ 프로 │ 슬러그      [ kim-oo         ] 🔒         │
│ 필   │ 표기명      [ 김OO           ]            │
│ 내   │ 표기 유형   ( )실명  (•)닉네임             │
│ 프로 │ 이미지      [ 업로드 ]                    │
│ 젝트 │ 기수        [ 1기            ] 🔒         │
│ ──   │ 소개·이력   [ + ]                         │
│ 교육 │ ── 공개 설정 ────────────────             │
│ 🔒   │ 공개 여부   [ ○ 비공개 ] 🔒               │
│ 계정 │ 상단 고정   ☐ 🔒                          │
│ 🔒   │ 정렬 순서   [ 12 ] 🔒                     │
│      │ [ 저장 ]     최종 수정 08-07 14:20        │
└──────┴───────────────────────────────────────────┘
        🔒 = builder 역할 잠금 (서버 강제)
```

- 잠긴 필드는 **비활성으로 보이되 수정되지 않는다** — 무엇이 있는지는 알되 못 바꾼다
- **잠금은 화면이 아니라 서버가 강제한다** (REQ-N-011)
- **공개 여부를 관리자만 쥐는 것이 품질 게이트다.** 별도 승인 워크플로가 필요 없다

**내 프로젝트 — 공동 담당 건 처리 (G-3b)**

```
┌──────────────────────────────────────────────────┐
│ ▓▓▓ 내 프로젝트                                   │
│ ┌────┐ 프로젝트 A          [ 수정 ]   ← 대표      │
│ ┌────┐ 프로젝트 B          [ 수정 ]   ← 대표      │
│ ┌────┐ 프로젝트 C [공동] 🔒  보기만   ← 참여      │
│        대표: 이OO                                 │
└──────────────────────────────────────────────────┘
```

**담당자 중 대표 1인만 편집한다.** 참여 건은 조회만 가능하며 대표가 누구인지 표시한다.

> **안전한 기본값이다.** 담당이 복수(N:M)이므로 전원이 편집하면 덮어쓰기가 발생한다.
> **디자인·개발 완료 후 재검토**하되, 넓히는 방향은 RLS 조건 완화만으로 가능하고
> 좁히는 방향은 기존 데이터에 대표를 손으로 지정해야 하므로 **좁게 시작한다.**
>
> 구현은 조인 테이블의 `is_owner` 플래그 + RLS `UPDATE` 조건 한 줄이다.

- 접근 권한은 관리자로 한정한다 (FN-A07-10). **발주사 확인 필요**
