## 1. 개요

### 1.1 목적

본 문서는 구축 대상 화면을 식별하고 경로·렌더링 방식·진입 경로를 정의한다. 확정된 화면 수는 범위 판정의 기준선이 되며, 본 문서에 없는 화면은 범위 외로 간주한다.

### 1.2 적용 범위

| 구분 | 대상 |
|---|---|
| 포함 | 공개 화면, 관리 화면, 시스템 화면의 식별·경로·전이 |
| 제외 | 화면별 기능 동작(『기능 명세』), 레이아웃(『화면 설계』), 경계 규칙(『정책 정의』) |

### 1.3 참조 문서

| 문서명 | 문서 번호 | 관계 |
|---|---|---|
| 요구사항 정의서 | ABG-REQ-001 | 상위 |
| 요구사항 정의서 상세 | ABG-REQ-001-A | 근거 |
| 기능 명세 | ABG-FN-003 | 하위 |
| 정책 정의 | ABG-POL-004 | 하위 |
| 화면 설계 (와이어프레임) | ABG-WF-005 | 하위 — 미작성 |

## 2. 화면 식별 체계

### 2.1 화면 ID 규칙

| 접두 | 구분 | 범위 |
|---|---|---|
| P-nn | 공개 화면 | 비인증 사용자 접근 가능 |
| A-nn | 관리 화면 | 인증 필요. noindex |
| S-nn | 시스템 화면 | 오류·상태 페이지 |

### 2.2 렌더링 구분

| 표기 | 방식 | 적용 기준 |
|---|---|---|
| SSG | 정적 생성 | 콘텐츠 변경 빈도가 낮은 화면 |
| SSG+ISR | 정적 생성 + 증분 재생성 | 콘텐츠 관리자가 수정하는 화면 |
| SSR | 서버 렌더링 | 요청 시점 데이터가 필요한 화면 |
| CSR | 클라이언트 렌더링 | 관리 화면 |

> 공개 화면은 서버에서 콘텐츠가 포함된 HTML을 반환해야 한다(REQ-N-001). CSR 단독 적용은 검색 색인 및 답변엔진 인용이 성립하지 않으므로 공개 영역에서 사용하지 않는다.

### 표기 규칙 (문서 공통)

| 표기 | 용도 |
|---|---|
| **굵게** | **판정 · 금지 조건에만 사용한다.** "~하지 않는다", "~시 불합격", "미노출", "차단" |
| `코드` | 수치 · 등급 · 경로 · 속성값 |
| 평문 | 그 외 전부 |

굵게 표시된 문장은 **검수 시 판정 대상**이다. 강조 목적으로 사용하지 않는다.

### 2.3 색인 구분

| 표기 | 의미 |
|---|---|
| 색인 | sitemap.xml 포함, 검색 색인 대상 |
| 비색인 | noindex 처리, sitemap 제외 |

## 4. 사이트맵

```
/                                     P-01  랜딩
│
├── /about                            P-02  회사 소개                    [P2]
│
├── /portfolio                        P-03  포트폴리오 목록
│   └── /portfolio/{slug}             P-04  프로젝트 상세          (색인 핵심)
│
├── /builders                         P-05  빌더 목록
│   └── /builders/{slug}              P-06  빌더 상세              (영업 자료)
│
├── /courses                          P-07  교육 과정 목록               [P1]
│
├── /process                          P-09  일하는 방식
├── /contact                          P-10  문의
├── /privacy                          P-11  개인정보처리방침
│
├── /insights                         P-12  인사이트 목록
│   ├── /insights/before              └ 카테고리 · 맡기기 전에
│   ├── /insights/process             └ 카테고리 · 만드는 과정
│   ├── /insights/people              └ 카테고리 · 만든 사람들
│   └── /insights/{slug}              P-13  인사이트 상세
│
└── /admin                            A-05  대시보드                     [비색인]
    ├── /admin/login                  A-01  로그인
    ├── /admin/builders               A-02  빌더 관리
    ├── /admin/projects               A-03  프로젝트 관리
    ├── /admin/courses                A-04  교육 과정 관리               [P1]
    ├── /admin/my                     A-06  빌더 개인 관리
    └── /admin/insights               A-07  인사이트 관리

── 범위 외 (제외 확정) ──────────────────────────────
    (/faq/{category})                 안건 3 — 제외
── 2차 ─────────────────────────────────────────────
    (/community)                      1기 수료 후
    (/builders/cohort/{n})            인원 50명 초과 시
```

최대 뎁스 2단. — 상세 화면 하위에 추가 계층을 두지 않는다.

**인사이트 카테고리 경로의 예약어 규칙 (v3.1)** — 카테고리 경로 `/insights/{category}` 와 글 경로 `/insights/{slug}` 가 같은 계층을 공유한다. 뎁스 2단 원칙을 지키기 위한 선택이며, 충돌을 막기 위해 다음을 적용한다.

| 항목 | 규칙 |
|---|---|
| 예약어 | `before` · `process` · `people` 3개를 카테고리 전용으로 예약한다 |
| 슬러그 검증 | 글 슬러그가 예약어와 같으면 저장을 거부한다 (A-07 검증) |
| 해석 순서 | 예약어를 먼저 카테고리로 해석하고, 그 외를 글 슬러그로 해석한다 |

> 글 슬러그는 자연어 한글을 쓰므로(REQ-F-092) 영문 예약어와 충돌할 가능성은 낮으나, 규칙이 없으면 영문 슬러그 입력 시 카테고리 목록이 가려진다. 검증을 A-07에 두는 이유다.

| 3 | 모든 프로젝트 카드는 P-04로 가는 링크를 보유한다. 고아 페이지를 만들지 않는다 | REQ-F-012a·079 |
| 4 | P-06의 프로젝트는 요약 카드로 인라인 전개한다. 전문은 P-04에 둔다 | REQ-F-021 |

### 5.2 카드 링크 구조

프로젝트 카드는 목적이 다른 링크 두 개를 보유한다.

| 링크 | 목적지 | 목적 | 필수 |
|---|---|---|:---:|
| 제목 · 자세히 보기 | P-04 프로젝트 상세 | 색인 경로 확보 | 필수 |
| 바로가기 | 외부 실제 서비스 | 신뢰 확보 | 링크 등급에 따름 |

> 링크 등급이 `none`인 경우 바로가기 버튼을 노출하지 않는다(POL-03). 단, 상세 진입 링크는 등급과 무관하게 항상 존재한다.
>
> 주 버튼과 보조 버튼의 시각적 위계는 『화면 설계』에서 확정한다.

### 5.3 전이 — 빌더 · 교육

```
P-05 빌더 목록
   │ 카드
   ▼
P-06 빌더 상세
   │
   ├── 프로젝트 카드 ──────────▶ P-04
   │
   ├── 수료 과정 — 텍스트만 표시 (P-08 폐지로 링크 없음, v3.2)
   │
   └── 문의 CTA ───────────────▶ P-10

P-07 교육 목록
   │ 카드
   ▼
(교육 과정 상세 없음 — 목록에서 커리큘럼을 바로 펼쳐 보여준다, v3.2)
```

양방향 연결 필수 경로

| 관계 | 방향 | 관련 요구사항 |
|---|---|---|
| 프로젝트 ↔ 빌더 | 양방향 | REQ-F-015 |
| 빌더 ↔ 교육 과정 | 양방향 | REQ-F-024·031 |

### 5.4 전이 — 문의

```
P-01 랜딩          ─┐
P-04 프로젝트 상세  ├──▶  P-10 문의  ──▶  플러그 폼 제출  ──▶  영업팀
P-06 빌더 상세      ─┘         │
                              └─ URL 파라미터: ref, builder, utm_source
```

| 진입 화면 | CTA 문구 | 부착 파라미터 |
|---|---|---|
| P-01 랜딩 | 프로젝트 상담하기 | `utm_source=home` |
| P-04 프로젝트 상세 | **비슷한 프로젝트 상담하기** *(v3.0 변경)* | `ref={project-slug}` · `utm_source=portfolio` |
| P-06 빌더 상세 | 이 빌더의 경험으로 상담받기 | `builder={builder-slug}` · `utm_source=builder` |

> **v3.0** — P-04 문구를 "의뢰하기"에서 "상담하기"로 변경해 3종의 부담 수위를 통일했다. 근거는 REQ-F-055 개정 사유 참조. 아울러 P-01 히어로·문의 섹션의 CTA 하단에 **마이크로카피**(텍스트, 링크 아님)가 추가된다 — REQ-F-056 · FN-C03-05.

> 파라미터는 **최소한 GTM이 수집하여 GA4 이벤트에 전달**한다. 리드 자체에 출처를 싣는 방식은 안건 10에서 확정한다. 발주사가 플러그 파라미터 주입이 가능하다고 확인했으며 가이드 문서 수령 후 REQ-C-002를 정정한다.

### 5.5 전이 — 관리

```
A-01 로그인
   │ 인증
   ▼
A-05 대시보드
   ├──▶ A-02 빌더 관리      ─ 목록 / 등록 / 수정
   ├──▶ A-03 프로젝트 관리  ─ 목록 / 등록 / 수정
   └──▶ A-04 교육 과정 관리 ─ 목록 / 등록 / 수정
```

미인증 상태로 `/admin/` 접근 시 A-01로 이동한다. 권한 판정은 서버에서 수행한다**(REQ-N-011).

## 6. URL 설계 규칙

### 6.1 기본 규칙

| 항목 | 규칙 | 관련 요구사항 |
|---|---|---|
| 슬러그 | 자연어(한글) 허용. **발행 후 변경 금지** | REQ-N-013 |
| 프로젝트 슬러그 | 검색어와 일치시킨다 (예: `/portfolio/에어로케이`) | REQ-F-012 |
| 대소문자 | 소문자 통일. 대문자 경로는 301 리다이렉트 | — |
| 후행 슬래시 | 미사용. 존재 시 301 리다이렉트 | — |
| 도메인 | www ↔ 루트 중 한쪽으로 통일 후 301 | 매뉴얼 §05 |

### 6.2 탭·필터 URL 규칙

**탭과 필터를 JavaScript 상태로만 처리하지 않는다. 각각 고유 경로를 부여한다**(REQ-F-074).

| 효과 | 내용 |
|---|---|
| 분석 | GA4·GTM에서 별도 페이지뷰로 집계된다 |
| 검색 | 각 경로가 독립 색인 대상이 된다 |
| 공유 | 특정 탭 상태를 링크로 공유할 수 있다 |

적용 대상

| 대상 | 경로 |
|---|---|
| 교육 과정 | `/courses/{과정슬러그}` |
| 포트폴리오 분류 필터 | `/portfolio/category/{분류}` — **2차.** v1은 필터를 두지 않는다 |

> 경로 충돌 주의 — `/portfolio/{slug}`가 상세를 점유하므로 `/portfolio/education` 형태의 필터 경로를 사용할 수 없다. 2차에서 필터를 도입할 경우 `/portfolio/category/{분류}` 네임스페이스를 사용한다.

### 6.3 canonical 규칙

| 항목 | 규칙 |
|---|---|
| 적용 범위 | 전 공개 화면에 self canonical |
| 교차 정규화 | 미적용 |

교차 정규화를 하지 않는 이유 — P-06(빌더 상세)의 프로젝트 요약과 P-04(프로젝트 상세)의 전문을 하나로 묶으면 한쪽이 색인에서 제외된다. 두 화면은 독립된 검색 진입점이므로 각각 색인되어야 한다.

중복 콘텐츠 해소 방식 — 분량을 달리한다.

| 화면 | 콘텐츠 | 분량 |
|---|---|---|
| P-06 빌더 상세 | 프로젝트 요약 | 40자 이상 1~2줄 |
| P-04 프로젝트 상세 | 본문 전문 | 500자 이상 |

> self canonical을 생략하면 UTM 파라미터가 부착된 URL이 별개로 색인될 수 있다.

## 7. 공통 컴포넌트

화면 간 재사용되는 컴포넌트다. 각 화면에서 동일하게 동작해야 한다.

| ID | 컴포넌트 | 사용 화면 | 비고 |
|---|---|---|---|
| C-01 | 프로젝트 카드 | P-01 · P-03 · P-06 | 링크 2개 보유(§5.2) |
| C-02 | 빌더 카드 | P-01 · P-05 | 표기 수위 혼재 대응 |
| C-03 | 문의 CTA | P-01 · P-04 · P-06 | 위치별 문구 차별화 |
| C-04 | 헤더 · GNB | 전체 공개 화면 | 상단 CTA는 문의로 수렴 |
| C-05 | 푸터 | 전체 공개 화면 | 개인정보처리방침 링크 상시 노출 |

C-01 프로젝트 카드는 세 화면에서 동일 컴포넌트를 사용한다. 화면별로 별도 카드를 만들지 않는다. 단, P-06(빌더 상세)에서는 담당 빌더 표기를 생략한다.

카드 구성 항목은 『기능 명세』에서 확정한다.

### 8.1 sitemap.xml 포함 기준

| 구분 | 포함 |
|---|:---:|

**절대경로로 기재하며, 404·noindex·리다이렉트 URL을 포함하지 않는다**(매뉴얼 §05).

### 8.2 색인 우선순위

| 순위 | 화면 | 근거 |

| 2 | P-03 포트폴리오 목록 | "바이브코딩 포트폴리오" 류 키워드 착지 페이지 |
| 3 | P-01 랜딩 | 브랜드·메인 키워드 |
| 4 | P-06 빌더 상세 | 인물 단위 진입점 |

### 8.3 내부 링크 무결성

고아 페이지 0건이 검수 기준이다(REQ-F-079).

| 화면 | 진입 경로 |
|---|---|
| P-04 | P-01 카드 · P-03 카드 · P-06 인라인 카드 · sitemap · 외부 검색 |
| P-06 | P-05 카드 · P-01 카드 · P-04 담당 빌더 링크 |

각 상세 화면은 최소 2개 이상의 내부 진입 경로를 보유한다.

## 9. 미결 사항

**v1.0의 안건 6건이 전부 정리됐다.** v3.1에서 안건 2가 정정되어 화면 수가 19 → 22종으로 변동됐다.

| 안건 | 항목 | 결정 | 화면 영향 |
|:---:|---|---|---|
| 1 | 관리자 권한 구조 | **2단 역할** | **A-06 추가 (+1종)** |
| 2 | 인사이트 / 블로그 | **포함** *(v3.1 정정)* | **P-12·P-13·A-07 추가 (+3종)** |
| 3 | FAQ 페이지 | **제외** | 없음 |
| 4 | 부가 신뢰 섹션 | **제외** | 없음 |
| 5 | 포트폴리오 목록 분리 | **분류축 교체.** 단일 목록 유지 | 없음. `(P-03a)` 소멸 |
| 6 | 랜딩 섹션 순서 | **포트폴리오 → 빌더** | P-01 섹션 배치 |

### 9.1 남은 미결 — 화면 영향 없음

| 안건 | 항목 | 왜 영향이 없나 |
|:---:|---|---|
| 10 | 문의 출처 추적 | **플러그 임베드 영역 내부** 사안이다. `P-10`의 레이아웃과 경로가 바뀌지 않는다 |
| 9 | 이관 정책 공개 | `P-09` 내 문단 유무. 화면 추가·삭제가 아니다 |

### 9.2 화면 수 확정

| 구분 | 수량 |
|---|:---:|
| **확정 범위** | **22종** *(v3.1)* |
| 2차 대상 | `(P-05a)` · `(P-16)` |
| 제외 확정 | `(P-14)` · `(P-15)` |

> **22종이 범위 기준선이다.** 『화면 설계』(ABG-UI-005)는 19종 기준으로 작성됐으므로 인사이트 3종에 대한 보강이 필요하다 — v3.1에서 §P-12·P-13·A-07 절을 추가했다.
