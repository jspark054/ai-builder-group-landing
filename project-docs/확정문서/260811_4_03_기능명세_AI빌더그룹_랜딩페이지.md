## 1. 개요

### 1.1 목적

본 문서는 『화면 목록(IA)』에 정의된 각 화면의 기능 동작과 인수 기준을 기술한다. 개발 착수의 직접 기준이며, 검수 시 판정 근거가 된다.

### 1.2 적용 범위

| 구분 | 대상 |
|---|---|
| 포함 | 화면별 기능 동작, 입출력, 인수 기준, 예외 처리 |
| 제외 | 경계 규칙 및 정책값(『정책 정의』), 레이아웃(『화면 설계』), 데이터 구조·API(TRD) |

> 본 문서는 동작을 정의하고, 『정책 정의』는 경계에서의 판정 규칙을 정의한다. 값(글자 수, 등급, 빈 상태 처리 등)은 정책 문서를 참조하며 본 문서에서 중복 기재하지 않는다.

> **v4.5 — 디자인 방향 확정.** 두 시안(정적 카피 중심 / 섹션별 인터랙션 다양화) 중
> 클라이언트가 **인터랙션 다양화 시안**을 "더 AI스럽지 않다"고 판단해 채택했다 —
> POL-11①-1이 클라이언트에게 직접 검증된 것이다. 단 **완성도를 더 높일 것**을 요구했으므로,
> 다음 단계의 초점은 새 화면 추가가 아니라 **상세 페이지 디자인 · 마이크로 인터랙션 ·
> 카피 다듬기**다. 결정시트 `I-2` 참조.

## 2. 기능 식별 체계

### 2.1 기능 ID 규칙

```
FN-{화면ID}-{일련번호}
```

| 예시 | 의미 |
|---|---|
| FN-P04-01 | 프로젝트 상세 화면의 1번 기능 |
| FN-C01-03 | 공통 컴포넌트 C-01의 3번 기능 |
| FN-COM-02 | 전 화면 공통 기능 2번 |

### 2.2 기능 구분

| 구분 | 정의 |
|---|---|
| 표시 | 데이터를 화면에 렌더한다 |
| 이동 | 다른 화면 또는 외부로 전이한다 |
| 입력 | 사용자 입력을 받는다 |
| 처리 | 서버 측 연산·저장을 수행한다 |
| 연동 | 외부 서비스와 통신한다 |

### 표기 규칙 (문서 공통)

| 표기 | 용도 |
|---|---|
| **굵게** | **판정 · 금지 조건에만 사용한다.** "~하지 않는다", "~시 불합격", "미노출", "차단" |
| `코드` | 수치 · 등급 · 경로 · 속성값 |
| 평문 | 그 외 전부 |

굵게 표시된 문장은 **검수 시 판정 대상**이다. 강조 목적으로 사용하지 않는다.

### 2.3 인수 기준 표기

각 기능은 검증 가능한 인수 기준을 갖는다. "잘 동작한다" 같은 서술을 사용하지 않으며, 관찰 가능한 결과로 기술한다.

## 3. 공통 컴포넌트 명세

### 3.1 C-01 프로젝트 카드

사용 화면 P-01(랜딩 섹션) · P-03(포트폴리오 목록) · P-06(빌더 상세 인라인)

세 화면에서 동일 컴포넌트를 사용한다. 화면별로 별도 카드를 구현하지 않는다.

| 기능 ID | 구분 | 기능 | 인수 기준 | 요구사항 |
|---|---|---|---|---|
| FN-C01-01 | 표시 | 실제 화면 썸네일을 표시한다 | 이미지 렌더 및 alt 속성 존재 | REQ-F-064 |
| FN-C01-02 | 표시 | 프로젝트명을 표시한다 | 제목 렌더 | — |
| FN-C01-03 | 표시 | 요약을 1~2줄로 표시한다 | 최소 분량 충족 (POL-04) | REQ-F-011 |
| FN-C01-04 | 표시 | 담당 빌더명을 표시한다. 복수인 경우 "OOO 외 N명"으로 표기한다 | 단수·복수 표기 각각 확인 | — |
| FN-C01-05 | 표시 | **분류 배지를 최대 2개까지 표시한다** | `category.sort_order` 앞선 것부터. 미지정 시 미표시 | REQ-F-018 |
| FN-C01-06 | 이동 | 제목 또는 "자세히 보기" 클릭 시 P-04로 이동한다 | 모든 카드에서 P-04 도달 가능 | REQ-F-012a |

예외 처리

| 상황 | 처리 |
|---|---|
| 썸네일 미등록 | 등록 불가 처리. 카드 렌더 대상에서 제외 (POL-02) |
| 링크 등급 `none` | 바로가기 버튼만 미노출. 콘텐츠와 상세 진입 링크는 유지 |

> **FN-C01-06은 삭제 불가 기능이다.** 이 링크가 없으면 P-04가 고아 페이지가 되어 색인되지 않으며, 본문 500자 작성이 무효가 된다.

**FN-P01-32 사유** — 이 자리는 동영상이 들어갈 자리이나 소스가 없어 정지 화면이다. 라벨이 없으면 컨펌 자리에서 *"영상이 빠졌다"* 로 오해된다. **동영상 수급 후 라벨을 제거하고 `<video>`로 교체한다.**

**FN-P01-31 → FN-P01-37 대체 사유 (v4.4)** — 「아래로 스크롤」 문구는 히어로에서 유일하게 지시적인 문장이라 카피 톤(POL-13)과 어긋났다. 기호(셰브론)로 바꾸면 같은 기능을 하면서 읽을 문장이 늘지 않는다.

**스크롤 구동 애니메이션 구간 계산 (v4.4 · 필독)** — 범위는 **반드시 sticky가 붙어 있는 창 안**에 들어와야 한다. 계산식은 아래 하나뿐이다.

`zone-dark` 의 **하단 패딩은 0이어야 한다.** 문제 섹션이 밝게 열리며 끝나는데 그 뒤에 네이비 패딩이 남으면, 애니메이션이 정상인데도 같은 증상(가운데 네이비 띠)으로 보인다.

**목업 데이터 주의 (v4.4)** — 빌더 사진은 목업에 넣지 않는다. 원형 프레임은 **테두리만** 보이는 것이 확정 디자인인데, 회색 플레이스홀더를 채우면 컨펌 자리에서 다른 디자인으로 읽힌다. 실제 증명사진은 **발주사 제공 대기**.

**FN-P01-23 개정 (v4.2)** — 그라디언트로 서서히 섞던 것을 **wipe**로 바꿨다. 밝은 면이 위에서 아래로 덮으며 들어온다. 경계가 분명해야 "장면이 바뀌었다"로 읽히고, 그라디언트 구간(60vh)이 아무 내용 없이 길게 비어 있던 문제도 사라진다.

**FN-P01-22 삭제 사유 (v4.0)** — 마그네틱 스냅을 제거했다. `proximity`는 체감되지 않고, `mandatory`는 섹션 2에서 사용자를 튕겨내(실측 1535px) 쉼 지점을 심어야 겨우 동작했다. 얻는 것에 비해 구조가 복잡해져 걷어냈다.

**FN-P01-26 사유** — 기수 배지(1기·2기)는 발주자에게 판단 근거가 되지 않고 오히려 경력이 짧다는 인상만 준다. 소구점 2의 근거는 **인원과 얼굴**이므로 전원을 크게 노출한다.

⚠️ **FN-P01-24·25의 미해결 항목** — 빌더 얼굴은 **실제 사진이 없으면 이니셜 아바타로 대체**된다. 증명사진 일러스트는 하드 룰 1(이미지 생성 금지)로 제작할 수 없으므로 발주사 수급이 필요하다. 섹션 3 우측도 **동영상이 아니라 정지 화면**이다 — 동영상 소스가 없다.

**FN-P01-20 주의 — POL-13과의 긴장.** POL-13은 *"R1 인용은 답(R3)보다 작고 연해야 한다. 인용이 답보다 강해지면 불안을 파는 인상이 되어 공포 마케팅 금지에 저촉된다"* 고 규정한다. v3.7에서 **크기·굵기를 같게 했으므로 "작아야 한다"는 조건은 더 이상 충족하지 않는다.** 색을 `--color-muted`로 유지해 "연해야 한다"만 지킨다. 발주사 지시에 따른 변경이며, 인용이 과하게 읽히는지는 시안 검수에서 확인한다.

**FN-P01-22 개정 (v3.8) — `mandatory` + 섹션 내부 쉼 지점.**

`proximity`는 임계값이 좁아 마그네틱이 체감되지 않았다(실측: 경계에서 40px 밖이면 걸리지 않음). `mandatory`로 올렸으나, 그것만으로는 **섹션 2(280vh) 한가운데에서 1535px 튕겨나갔다** — 스냅 지점이 하나도 없는 긴 구간에서는 브라우저가 양 끝으로 끌어당기기 때문이다. 순차 등장 구간을 통째로 못 쓰게 된다.

해결 — 섹션 2 안에 **보이지 않는 쉼 지점 3개**(`.problem-rest`, 16% · 44% · 72%)를 둔다. 각 문장이 드러난 직후 지점이라 스냅이 걸려도 연출이 끊기지 않는다. 실측 결과 한가운데 체류 오차 25px.

화면이 낮은 환경(`max-height: 640px`)에서는 섹션이 뷰포트보다 커질 수 있으므로 `proximity`로 물러선다.

**FN-P01-16·19 구현 방식** — `position: sticky` + 스크롤 구동 애니메이션(`view-timeline`)으로만 만든다. JS로 `wheel`을 가로채면 키보드·트랙패드 사용자가 섹션에서 빠져나가지 못하는 사고가 난다. 스크롤 자체는 평소대로 동작하고, 화면에 붙는 것은 CSS sticky다.

미지원 브라우저에서는 **고정도 순차 등장도 없이 처음부터 전부 보인다**(점진적 향상). `prefers-reduced-motion: reduce` 에서는 높이를 되돌리고 마퀴를 멈춘다 — 되돌리지 않으면 빈 화면만 길게 남는다.

**마퀴는 장식이다.** 실제 포트폴리오는 섹션 4가 담당하므로 `aria-hidden` 처리하고 `alt`를 비운다. 같은 정보를 스크린리더에서 두 번 읽히지 않게 한다.

**FN-P01-15 근거** — toktokhan.dev 히어로 H1의 실측값(Chrome `getComputedStyle` · 인라인 선언)을 그대로 옮긴 것이다. 발주사가 자사 사이트에서 쓰는 값이므로 "AI스럽지 않은" 기준선에 대한 별도 협의가 필요 없다. `clamp`를 쓰므로 반응형 분기를 따로 두지 않는다.

| 속성 | 값 | 출처 |
|---|---|---|
| font-weight | 700 | 실측 그대로 |
| font-size | `clamp(30px, 3.9vw, 52px)` | **최대값만 60 → 52px로 낮춤 (v3.9)** |
| line-height | 1.24 | 실측 그대로 |
| letter-spacing | -0.03em | 실측 그대로 |

**최대 크기를 낮춘 이유 (v3.9)** — 우리 H1이 발주사 사이트보다 길다. 저쪽은 「AI 도입을 넘어 / 일하는 방식을 바꿉니다」 두 줄이지만, 우리는 첫 줄에 서비스 범주(「AI 홈페이지 제작·앱 개발」)가 들어간다. 60px에서는 줄이 화면을 가득 채워 답답해진다. **굵기·행간·자간은 실측값 그대로 유지**한다.

권한 표시 규칙

**잠긴 필드는 비활성 상태로 보이되 수정되지 않는다.** 무엇이 있는지는 알되 바꿀 수 없게 한다. 숨기면 빌더가 관리자에게 무엇을 요청해야 하는지 알 수 없다.

**잠금은 화면이 아니라 서버가 강제한다** (REQ-N-011). 프론트엔드 은닉으로 대체하지 않는다.

| 세션 만료 | `A-01`로 이동. 복귀 후 원래 화면으로 |

> **공동 담당 프로젝트는 대표 1인만 편집한다.** 담당이 복수(N:M)이므로 전원이 편집하면 덮어쓰기가 발생한다. 디자인·개발 완료 후 재검토하되, 넓히는 방향은 권한 조건 완화만으로 가능하므로 **좁게 시작한다.**
