### 1. P-01 카피 — 신규 작성본 B안 전체 채택

**판단**: 「`카피후보_박진선_P01_v1.md`」의 **B안(신뢰 중심) 8섹션 + CTA 전문**을 채택한다. 기획-2안은 폐기한다.

| 항목 | 내용 |
|---|---|
| 시점 | **전 문장 방문자 시점으로 통일.** "우리가 이렇게 합니다"가 아니라 "당신이 이걸 확인할 수 있습니다" |
| 참조 범위 | 기획안 · PRD · 확정문서. **팀 공유 후보집(`archive/`)은 미사용** — 기존 문장에 영향받지 않은 상태로 새로 쓰는 것이 작성 목적이었다 |
| 관리 방식 | `apps/web/content/p01-copy.ts` 한 파일. 섹션별 상수로 구조화하고 컴포넌트는 문장을 직접 갖지 않는다 |
| 적용 범위 | 히어로만 화면 연결. **02~08은 상수만 준비**하고 조립 시 `p01Copy`에서 꺼내 쓴다 |

**A안(확인 중심)을 쓰지 않은 이유** — A안은 "다 열어볼 수 있다"는 인상이 라이브 링크 물량에 전적으로 의존한다. PRD §12 리스크대로 "상" 등급이 8건에 미달하면 카피가 근거보다 앞서 나간다. 물량 판정 전에는 물량과 무관하게 성립하는 B안이 안전하다. **판정 결과가 8건 이상이면 A안 재검토 대상이다.**

### 2. 히어로 카피 — FR-1.7 미확정 상태에서 임의 결정

**판단**: 회신을 기다리지 않고 **본사 관계 표기 최소 수위**로 진행한다.

| 항목 | 내용 |
|---|---|
| 본사 표기 | **본사를 주어로 세우지 않는다.** "본사가 보증한다" 취지의 문장을 두지 않는다 |
| 신뢰의 근거 | 조직 관계가 아니라 **일하는 방식 · 검증 절차**로 구성한다 (확정 소구점 1·3) |
| 전제 | **발주사 확인 후 교체를 전제한 잠정 결정이다.** FR-1.7 회신과 발주사 컨펌(POL-13) 시 교체한다 |

**교체 비용을 미리 낮춰 둔 방식** — 카피가 상수 파일 한 곳에 모여 있어 회신이 오면 그 파일만 바꾸면 된다. 컴포넌트에 문장이 박히지 않으므로 어디까지가 컨펌 대상인지 추적이 끊기지 않는다.

**FR-1.7이 어느 쪽으로 회신되든 문장이 무효가 되지 않는다.** A안(관계 명시)이면 표기를 더하는 작업이고, B안(별도 브랜드)이면 그대로 둔다. 종전 카피는 B안 회신 시 근거를 잃는 구조였다.

**판단**: 히어로에 배경 영상과 PAUSE 컨트롤을 **두지 않는다.**

## 스키마 구현 결정 (2026-08-16)

`packages/supabase/migrations/0002_ai_builder_group.sql` 작성 시 판단한 것이다.
기준은 『데이터 모델』(ABG-DM-006) v1.2이며, 테이블 8종·RLS·인덱스를 그대로 옮겼다.

### 1. 컬럼 단위 UPDATE 제한 — GRANT 대신 RLS, 일부 미구현

**문서**: §4.2가 빌더의 UPDATE에서 특정 컬럼을 제외하라고 규정하고, §4.3이 *"`GRANT UPDATE (컬럼목록)` 권장. DB가 강제"* 로 방법을 지정한다.

| 테이블 | 빌더가 못 바꿔야 하는 컬럼 |
|---|---|
| `builder` | `slug` · `cohort` · `is_public` · `is_pinned` · `pin_order` |
| `project` | `slug` · `is_public` · `sort_order` |

**판단**: **GRANT를 쓰지 않고 RLS 정책으로 간다.** Supabase에서 admin과 builder는 **모두 `authenticated` 롤**이라 롤 단위 GRANT로 둘을 가를 수 없다. 문서가 지정한 방법이 이 환경에서 그대로 성립하지 않는다. 대신 `is_admin()` · `my_builder_id()` 를 조건으로 하는 UPDATE 정책으로 **권한 범위(누가 어느 행을)** 를 강제한다.

> ⚠️ **컬럼 단위 제한은 이번 마이그레이션에 구현되지 않았다.**
> Postgres RLS는 행 단위다. `WITH CHECK`는 NEW 행만 보고 OLD를 참조하지 못해 *"이 컬럼 값이 안 바뀌었는지"* 를 검사할 수 없다. 남은 방법은 `BEFORE UPDATE` 트리거인데 데이터모델 문서에 정의돼 있지 않아 만들지 않았다.
>
> **현재 노출도** — 쓰기는 service role(관리자 서버 액션) 경유이고 빌더 셀프 편집 화면(A-06)이 아직 없어 실제 경로는 열려 있지 않다. **A-06 착수 전에 반드시 닫아야 한다.**
>
> **팀장 확인 필요** — 트리거를 추가할지, 서버 액션 필드 필터링(§4.3 "보조")만으로 갈지. 후자면 `REQ-N-011`(*"프론트엔드 은닉으로 대체하지 않는다"*, P0)과 충돌한다.

### 2. `project_builder` 익명 SELECT 차단 — 서버 조회 전제

**문서대로 `✕`로 구현했다.** 임의로 열지 않았다.

**전제**: 공개 화면(P-01 섹션 4 · P-04)의 담당 빌더 표기는 **서버 컴포넌트에서 서버 측 키로 조회**한다. anon 키로는 이 조인이 읽히지 않는다.

> **팀장 확인 필요** — 문서 §4.2에 비대칭이 있다. 바로 아래 `project_category`는 익명에게 *"공개 프로젝트분"* 을 허용하는데 `project_builder`만 전면 차단이다. **분류 배지는 anon으로 읽히고 담당 빌더는 안 읽힌다.** 의도된 것인지, 표 작성 시 누락인지 확인이 필요하다. FN-C01-04(*"OOO 외 N명"*)가 공개 카드의 필수 표기이므로 영향이 있다.

### 3. 시딩하지 않은 것 — `category` 초기 9건

§3.4가 `axis`·`name` 9건을 확정했으나 **`slug` 값을 정의하지 않았다.** slug는 URL이자 발행 후 변경 금지 대상(`REQ-N-013`)이라 임의 생성이 불가하다. 테이블만 만들고 9건은 SQL 주석으로 남겼다. **slug 확정 후 별도 시드로 넣는다.**

### 4. 넣지 않은 제약 2종

| 항목 | 근거 |
|---|---|
| 길이 상한 CHECK (`display_name` 40 · `summary` 120 · `bio` 200 · `title` 60) | §8이 *"초과 시 저장을 막지 않고 경고만 한다"* 로 규정. CHECK로 걸면 문서 위반 |

### 5. 슬러그 문자 규칙 — 패턴 제약을 두지 않는다

데이터모델 문서는 slug에 `UNIQUE`와 "발행 후 변경 금지"만 규정하고 **문자 규칙을 정의하지 않았다.** IA §6.1이 *"자연어(한글) 허용"* 이므로 ASCII 전용 같은 패턴 CHECK를 걸면 안 된다. `insight`에는 **예약어 CHECK만** 두었다.

```sql
constraint insight_slug_not_reserved
  check (slug not in ('before', 'process', 'people'))
```

## 실전 사례 5건 · 카테고리 시딩 (2026-08-17)

### 1. 실전 사례 대상 — 5건 확정

요구사항정의서 §4.2 표는 4건("차근차근 · 에듀셀파 3% · 동행케어 · 카본벨트")으로
기재하나, **8/4 발주사 회의록 원본(10:17) 대조 결과 5건**이다.

원문: *"제가 봤을 때 지금 이 차근차근 에듀셀파 3%랑 동행 케어 카본 벨트 정도는
다 바이브 코딩으로 하고 있는 거거든요."*

대상 5건: **차근차근 · 에듀셀파 · 3% · 동행케어 · 카본벨트**

§4.2 표기는 전사 시 "에듀셀파"와 "3%"를 한 덩어리로 묶은 오기다.
**확정문서 원본은 수정하지 않으며**, 본 절을 해석 기준으로 삼는다.

발주사 발언은 "이 정도는 넣어도 된다"는 **허용 범위**이지 전건 게재 의무가 아니다.
잔여 일정에 따라 5건 중 일부를 택한다. 위 5건 외 임의 대체는 불가하다.

부수 확인 — 발주사는 다인원 투입 건을 명시적으로 배제했다(같은 발언).

**게재 여부는 §6에서 다시 정한다.** 위 5건은 발주사가 허용한 *범위*이며,
§4.11에 따라 소개글 작성에는 발주사 제공 자료가 필요하다. 자료 미수령
상태이므로 실제 게재분은 §6을 기준으로 한다.

포함한다.

## C-01 프로젝트 카드 구현 결정 (2026-08-18)

`apps/web/components/cards/project-card.tsx` · `lib/queries/project-cards.ts` ·
`content/component-copy.ts` 신설. 기능명세 §3.1(FN-C01-01~08) 구현분이다.

### 1. 조회는 service role 로만 — 서버 전용 고정

`project_builder` 는 익명 SELECT 가 RLS 로 차단돼 있다 (「스키마 구현 결정」 §2).
익명 클라이언트로 부르면 **에러 없이 빌더가 빈 배열로 나온다.** 조용히 틀리는 경로다.

**판단**: 카드 쿼리는 `createAdminSupabase()`(service role)로 고정하고 서버 컴포넌트에서만 부른다.
`server-only` 패키지는 설치돼 있지 않아 의존성을 늘리지 않았다. 대신 service role 키가
클라이언트 번들에 없으므로 브라우저에서 호출하면 `requireConfig()` 단계에서 throw 한다 —
빈 값으로 조용히 넘어가지 않는다.

### 2. PostgREST 중첩 select 를 쓰지 않는다 — 평면 쿼리 4회

`packages/supabase/src/types.ts` 는 손으로 관리하는 타입이라 `Relationships` 가 비어 있다.
이 상태에서 `project_category(category(...))` 같은 중첩 select 는 결과 타입이 무너진다
(supabase-js 2.110 이 Relationships 로 조인을 해석한다).

**판단**: 관계 테이블을 평면으로 읽고 앱에서 합친다.
project → (project_category · project_builder 병렬) → (category · builder 병렬). SSR 1회 비용이라 감당 범위다.
`Relationships` 를 채우는 작업은 제출 후로 미룬다.

### 3. `types.ts` 에 테이블 5종 추가

`builder` · `project` · `category` · `project_builder` · `project_category` 의 Row 타입을
0002 마이그레이션 컬럼과 1:1 로 추가했다. 이게 없으면 `from('project')` 자체가 타입 에러다.
`course` · `insight` · `admin_user` · `site_setting` 은 읽는 화면이 아직 없어 넣지 않았다.

### 4. `<Link href>` 를 UrlObject 로 넘긴다 (한시적)

P-04(`/portfolio/[slug]`)가 아직 없어 typedRoutes 가 문자열 href 를 거부한다
(`Type 'string' is not assignable to type 'UrlObject | RouteImpl<string>'`).
Hero·Header 는 같은 이유로 `<a>` 를 썼지만, C-01 은 **제목 링크의 `::after` 로 카드 전체를
클릭 영역으로 만드는 구조**라 `<Link>` 가 필요하다.

Next 가 안내하는 `as Route` 캐스트는 `.next/types/link.d.ts` 의 모듈 보강에 의존한다.
생성물이 없는 환경에서 typecheck 가 깨지므로 쓰지 않았다.
대신 `href={{ pathname: '/portfolio/…' }}` — UrlObject 는 경로 검증 대상이 아니라 통과하고
런타임 동작도 같다. **P-04 를 만든 뒤 문자열 템플릿으로 되돌린다.**

### 5. 문서에 없어 판단한 것

- **`category.is_public` 필터를 걸지 않았다.** FN-C01-05 는 정렬(sort_order)과 상한(2개)만 정한다.
  필터를 걸면 배지가 소리 없이 사라지므로 연결된 분류는 그대로 표기한다
- **`builder.is_public` 필터도 걸지 않았다.** 카드의 빌더 표기는 이름 텍스트뿐이고 링크가 없다.
  P-05·P-06 목록 노출 조건과는 별개다
- **정렬 동순위** — `project.sort_order` 동값이면 `created_at` 오름차순. 문서에 없어 순서만 고정했다
- **호버 인터랙션 없음** — 카드 등장·확대 모션을 넣지 않았다 (POL-11①-2). 상태는 색 이동으로만 알린다

## P-01 섹션 4 조립 · 테이블 권한 사고 (2026-08-18)

### 1. 섹션 껍데기와 내용의 분리

`components/landing/Section.tsx` 는 **제목 슬롯 · 상하 여백 · 컨테이너 폭**만 갖는다.
배경·글자색은 넣지 않고 호출부가 `className` 으로 넘긴다 — P-01 은 교대가 아니라

껍데기가 그 표를 알고 있으면 섹션이 늘 때마다 이 파일을 고치게 된다.

내용은 `children` 이다. 2 인용 3문장 · 3 좌우 2단 · 4 카드 그리드 · 7 2행 4열 —
공통 구조가 없어서 슬롯을 더 만들면 섹션마다 예외가 붙는다.

### 2. 테이블 권한(GRANT) 누락 — 0004 신설

섹션 4 를 붙이자마자 `/` 가 500 이 났다.

    42501 permission denied for table project     (service role 도 동일)

REST 로 전 테이블을 확인한 결과 **0001 · 0002 로 만든 테이블 전부**가 anon ·
authenticated · service_role 어느 롤에도 테이블 권한이 없었다. 프로젝트 생성 시
**"Automatically expose new tables" 를 해제**한 상태에서 마이그레이션을 돌린 결과다
(devlog 8/16). 설정이 켜진 뒤 만든 0003 `site_setting` 만 정상이었다.

**RLS 정책 28건은 그동안 죽어 있었다.** GRANT 가 없으면 정책이 평가되기 전에 끊긴다.
카드 조회만의 문제가 아니라 읽기·쓰기 전 경로의 문제였다.

`0004_grants.sql` 로 Supabase 기본 권한과 같은 모양을 복원했다. 행 필터는 그대로 RLS 가
담당한다. `project_builder` 는 **anon 에 주지 않았다** — 익명 SELECT 차단이 의도한
설계이기 때문이다(「스키마 구현 결정」 §2). `admin_user` 도 롤에 직접 열지 않았다.
`is_admin()` · `my_builder_id()` 가 security definer 라 함수 안에서만 읽힌다.

### 3. `pnpm build` 가 루트 `.env` 를 읽지 않는다

`build` 스크립트만 `with-env.sh` 를 거치지 않아(dev · start 는 거친다) 프리렌더 시
`requireConfig()` 가 throw 하고 `/` 생성이 통째로 깨졌다.

**판단**: 쿼리 첫머리에 `isSupabaseConfigured()` 가드를 두고 미설정이면 경고 한 줄과 함께
빈 목록을 반환한다. 섹션은 POL-02 로 스스로 숨는다. **설정이 있는데 권한·질의가 틀린
경우는 그대로 throw** 한다 — 조용히 비는 것과 구분해야 한다.
Vercel 은 환경변수가 주입되므로 실렌더다.

근본 해결(`build` 도 with-env.sh 로 감싸기)은 로컬 빌드에 bash 의존이 생겨 마감 후로 미뤘다.

### 4. C-01 하단 버튼이 줄바꿈되던 원인

2칸 그리드 안에서 버튼 그룹이 카드 폭의 절반(약 160px)만 받는데 버튼 2개가 약 230px 이라
