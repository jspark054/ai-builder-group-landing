## 2. 핵심 전략 — 4단 신뢰 체인

### 2-1. 시장의 문제

클라이언트는 **선택지를 구분하지 못합니다.** 업체군(TenAI 등)은 서로 비슷해 보이고, 개인 프리랜서는 검증할 방법이 없습니다. **포트폴리오는 위조가 가능하기 때문입니다.**

### 2-2. 해법 — 위조하기 어려운 증거로 뒷받침

| 클라이언트의 의심 | 답하는 요소 | 위조 난이도 |
|---|---|---|
| "실제로 만든 게 있나?" | **포트폴리오** | 쉬움 ← 시장의 문제 지점 |
| "실력이 어디서 왔나?" | **교육 내역** | 어려움 |
| "이 조직이 계속 있나?" | **커뮤니티** | 어려움 |
| "맡기면 관리는 되나?" | **똑빌더** | 어려움 |

> 검증된 교육을 거친 사람이(교육) → 계속 활동하는 조직에 속해 있고(커뮤니티) → 실제로 이런 결과물을 만들었으며(포트폴리오) → 이 체계로 관리된다(똑빌더)

**인력 → 조직 → 결과물 → 프로세스**의 4단 체인. 네 요소가 독립 페이지로 흩어지면 인과가 끊기므로 **연결 자체가 요구사항**입니다.

### 2-3. 경쟁사 대비 우리가 채울 자리

조사 결과 아래 두 축이 시장에서 비어 있습니다.

1. **인력 실체 공개** — 업체는 대표만 노출, 개인은 조직이 없음. **실명 빌더 + 조직 보증** 형태는 어디에도 없음
2. **포트폴리오 검증 가능성** — 확인한 곳 모두 고객사명·이미지만 있고 **라이브 링크가 없음**

※ 2번은 §0-2의 미확정 항목(링크 공개 여부)에 걸려 있으므로 답변 확인 필요

## 4. 정보구조 (IA)

```
/ (메인)
├── 빌더(팀원) 리스트
│   └── 빌더 상세 → 해당 빌더의 프로젝트 인라인 전개
│       └── 각 프로젝트는 개별 URL도 보유 (/portfolio/<slug>)
├── 교육 · 커뮤니티 (빌더/프로젝트와 양방향 연결)
├── 일하는 방식 (똑빌더 소개)
├── 인사이트/블로그
│   └── 포스트 상세 (슬러그, OG 썸네일)
├── 프로젝트 문의 → 플러그 폼 임베드
└── /admin (관리자)
    ├── 빌더 관리
    ├── 프로젝트 관리 (노출 여부 토글)
    └── 블로그 포스트 관리
```

### 4-1. 포트폴리오 뎁스 구조 — 3안 채택

요구사항은 "한 뎁스 안에 다 보여준다"지만, 그대로 하면 개별 프로젝트가 자기 URL을 못 가져 프로젝트 단위 검색 진입점이 사라집니다.

| | 방식 | 뎁스 요구 | 프로젝트 SEO |
|---|---|:---:|:---:|
| 1안 | 빌더 페이지 인라인 전개만 | ○ | ✕ |
| 2안 | 프로젝트별 상세 페이지 분리 | ✕ | ○ |
| **3안 (채택)** | **인라인 전개 + 개별 URL 병행** | **○** | **○** |

중복 콘텐츠는 canonical로 정규화합니다.

## 9. 기술 스택 — orca-ai-company 기반 (필수)

> 전원 동일 환경 필수. 이유는 **관리 목적 + AI 최적화 환경에서의 업무 방식 평가**.

- Monorepo: pnpm workspaces + Turborepo
- Frontend: Next.js 16 (App Router) + React 19 + TypeScript 5.9 strict + Tailwind CSS 4
- 앱 구성: `apps/web`(:3000) + `apps/admin`(:3001)
- Backend/DB: 기본 파일(마크다운) 기반, `.env`에 Supabase 키 입력 시 `getRepository()`가 자동 전환
- 리치 에디터: tiptap / UI: Radix 기반 커스텀
- 배포: Vercel (개인 계정 → 산출물 전달)
- 이미지 생성: `pnpm imagegen` (Codex 사용, Claude 생성은 하드 차단)
- SEO/GEO 자동화: 템플릿 내장

### 9-1. 교체해야 할 부분

| 대상 | 내용 |
|---|---|
| `packages/content/src/schema.ts` | blog post 스키마 → builders / projects / education 스키마 |
| `packages/content/src/audit.ts` | 감사 규칙을 새 스키마 기준으로 |
| `wiki/03-*`, `wiki/04-*` | 도메인 가이드 문서 교체 |
| `agents/` | 선택 — 이번 스코프에 필수 아님 |

**그대로 유지**: 세션 컨텍스트 훅, 메모리 구조, 검수 게이트, 이미지 정책, 저장소 드라이버 패턴, SEO 자동화, 모노레포 뼈대
