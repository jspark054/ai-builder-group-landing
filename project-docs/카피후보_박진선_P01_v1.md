## 0. 이 문서의 전제

### 시점 — 전 문장 방문자 시점

> "우리가 이렇게 합니다"가 아니라 **"당신이 이걸 확인할 수 있습니다"**로 쓴다.
> 공급자가 자기 방식을 설명하는 문장은 후보에 넣지 않는다.

7 일하는 방식의 8단계 설명도 이 규칙을 적용해 **발주자를 주어로** 다시 썼다.
기능명세 §4.7의 단계 설명(기획-2안)은 수행사를 주어로 한 문장이므로 대체 대상이다 (§4.7 주석 — 팀원 재량 대체 가능).

### A안 / B안의 성격

| | A안 — 확인 중심 | B안 — 신뢰 중심 |
|---|---|---|
| 답하는 것 | 무엇을 검증할 수 있는가 | 확인한 결과 무엇을 얻는가 |
| 층위 | 동작 · 사실 | 기준 · 관계 |
| 문장 | 짧고 단정적 | 조금 길고 서술적 |
| 목적 | 리스크 해소 | 안심 |
| 읽고 난 인상 | "여기는 다 열어볼 수 있구나" | "여기는 모르는 채로 지나가는 구간이 없구나" |

**두 안은 같은 말의 다른 표현이 아니다.** A안은 방문자를 검증자로 세우고, B안은 방문자를 이미 판단을 마친 사람으로 대한다. 섹션 3에서 가장 크게 갈린다 — A안은 *물어볼 질문*을 주고, B안은 *답이 갈리는 지점*을 알려준다.

### 지킨 제약

| 제약 | 근거 |
|---|---|
| 본사(똑똑한개발자)를 주어로 세우지 않는다. "조직이 보증한다" 취지의 문장을 쓰지 않는다 | FR-1.7 미확정 |
| 신뢰의 근거는 조직 관계가 아니라 **일하는 방식 · 검증 절차**에 둔다 | 확정 소구점 1·3 |
| 교육을 전면에 내세우지 않는다. 6 섹션에 **"교육 과정 보기" CTA를 두지 않는다** | 회의록 260812 · P-07 범위 밖 |
| 수치 · 건수 · 기간을 쓰지 않는다 (8단계는 확정 사실) | POL-01 · FN-P01-08 |
| 경쟁사 실명 · 비교급 · 최상급을 쓰지 않는다 | REQ-F-005 · POL-13 |
| 사고 사례를 나열하지 않는다. 인용이 답보다 세지지 않게 한다 | REQ-F-004 · POL-13 공포 마케팅 금지 |
| 인용(R1)은 반드시 인용부호 안에 둔다 | POL-13 · FN-P01-11 |
| CTA는 문의로만 수렴한다. 보조 링크·버튼을 만들지 않는다 | REQ-F-007 |

## 01 히어로

정적 + 대표 프로젝트 · 모션 최소화 · CTA(C-03) · 스크롤 유도는 기호(FN-P01-37, 텍스트 0자).

| 구분 | 카피 |
|---|---|
| A안 (제목) | 직접 열어보고 고르세요 |
| A안 (서브) | AI 홈페이지 제작, AI 앱 개발<br>모든 프로젝트에 실제 서비스 주소가 걸려 있습니다. |
| B안 (제목) | 맡기기 전에 확인이 끝납니다 |
| B안 (서브) | AI 홈페이지 제작, AI 앱 개발<br>만든 사람과 진행 단계까지 보고 결정하실 수 있습니다. |

**서브 첫 줄은 두 안 공통이다.** SEO 키워드(FR-6.1 · 리드 유입 페이지 계열)를 담는 자리이고, 주장은 H1과 둘째 줄이 담는 분업 구조다. 첫 줄만 떼어 읽으면 어느 개발사에나 붙지만, 이 줄은 주장이 아니라 검색 통로다.

## 02 문제 제기

인용(R1) 1문장 + 본문(R2) 2문장 = **3문장.** 스크롤 구간마다 하나씩 등장한다(FN-P01-16).
제목을 두지 않는다 — 인용과 본문이 같은 크기이고 인용만 연하다(FN-P01-20).
사고 사례 나열 금지(REQ-F-004).

| 구분 | 카피 |
|---|---|
| A안 (인용 R1) | "포트폴리오는 다들 비슷해 보이던데요." |
| A안 (본문 1) | 캡처 화면만으로는 지금도 돌아가는 서비스인지 알 수 없습니다. |
| A안 (본문 2) | 누가 만들었는지는 대개 빠져 있습니다. |
| B안 (인용 R1) | "잘하는 곳인지 어떻게 알아보죠?" |
| B안 (본문 1) | 고를 근거가 이미지와 회사 소개뿐이면 판단이 감에 기댑니다. |
| B안 (본문 2) | 무엇을 볼지 정해져 있으면 비교는 어렵지 않습니다. |

**A안은 진단에서 끝내고 다음 섹션에 답을 넘긴다. B안은 두 번째 문장에서 이미 안심 쪽으로 방향을 튼다.** 이 차이가 두 안의 온도차가 시작되는 지점이다.

## 03 선택 기준

제목 + 기준 3종. 각 기준은 **인용(R1) + 답(R3)** 2행(FN-P01-11).
**순서는 소구점 1·2·3 고정**(FN-P01-12) — 결과물 → 사람 → 일하는 방식.
좌 텍스트 · 우 미디어 2단, 3종 순차 교체(FN-P01-25 · 34).
경쟁사 실명 금지.

| 구분 | 카피 |
|---|---|
| A안 (제목) | 세 가지를 물어보세요 |
| A안 (설명) | 후보가 여럿일 때 같은 질문을 던지면, 답할 수 있는 곳과 없는 곳이 갈립니다. |
| B안 (제목) | 볼 것이 정해지면 후보가 좁혀집니다 |
| B안 (설명) | 아래 세 가지를 던져 보면 답이 나오는 곳과 물어봐야 알 수 있는 곳으로 나뉩니다. |

### 기준 3종

| 구분 | 라벨 | 인용 (R1) | 답 (R3) |
|---|---|---|---|
| **A안 · 기준 1** | 열리는 결과물 | "그거, 지금도 돌아가나요?" | 받은 주소가 지금 접속되는지 보세요. |
| **A안 · 기준 2** | 이름이 붙은 담당자 | "실제로는 누가 만드나요?" | 그 화면을 만든 사람 이름을 물어보세요. |
| **A안 · 기준 3** | 모든 단계 고객 컨펌 | "중간에 어떻게 되는지 알 수 있나요?" | 단계마다 컨펌을 받는지 확인하세요. |
| **B안 · 기준 1** | 열어서 확인되는 결과물 | "화면만 보고는 모르겠어요." | 링크가 열린다면 그 결과물은 이미 증명된 것입니다. |
| **B안 · 기준 2** | 이름이 붙은 담당자 | "맡기면 누구랑 일하게 되나요?" | 담당자 이름이 붙어 있으면 물어볼 상대가 정해집니다. |
| **B안 · 기준 3** | 모든 단계 고객 컨펌 | "진행이 잘 되는 건지 모르겠어요." | 단계마다 컨펌을 거친다면 모르는 채로 지나가는 구간이 없습니다. |

- **기준 3 라벨 「모든 단계 고객 컨펌」은 결정시트 `H-4` 확정값이므로 두 안 모두 유지한다.**
- 기준 1·2 라벨은 확정값이 아니다. 라벨 길이가 3종 간에 크게 달라지면 순차 교체에서 눈에 띄므로 A안은 6~8자, B안은 9~11자로 맞췄다.
- 우측 미디어의 「동영상 예정」 라벨(FN-P01-32)은 카피가 아니라 수급 표시다. 소스 수령 시 제거.

## 04 포트폴리오 ★

제목 + C-01 카드 + 전체 보기(→ P-03). 공개 프로젝트 0건이면 섹션 숨김(POL-02).

| 구분 | 카피 |
|---|---|
| A안 (제목) | 눌러보면 그대로 뜹니다 |
| A안 (설명) | 카드의 바로가기는 지금 운영 중인 서비스로 갑니다. 만든 사람 이름도 카드에 함께 있습니다. |
| A안 (전체 보기) | 전체 보기 |
| B안 (제목) | 결과물부터 보고 오세요 |
| B안 (설명) | 캡처가 아니라 실제로 쓰이고 있는 화면입니다. 눈에 드는 결과물이 있으면 그 담당자에게 바로 닿습니다. |
| B안 (전체 보기) | 프로젝트 전체 보기 |

링크 등급 `none`인 프로젝트는 바로가기만 빠지고 상세 진입은 유지된다(POL-03). 두 안 모두 "전부 열린다"고 말하지 않는 이유다 — A안은 "카드의 바로가기는", B안은 "눈에 드는 결과물이 있으면"으로 범위를 한정했다.

## 05 빌더

제목 + C-02 카드. **전원 노출 · 기수 배지 없음**(FN-P01-26) · 외부 박스 없음(FN-P01-29) · 원형 사진 6×2(FN-P01-35). 전체 보기(→ P-05).

| 구분 | 카피 |
|---|---|
| A안 (제목) | 프로젝트마다 이름이 붙습니다 |
| A안 (설명) | 위 결과물을 맡은 사람들입니다. 얼굴을 누르면 이력과 담당한 작업이 한 화면에 펼쳐집니다. |
| A안 (전체 보기) | 전체 보기 |
| B안 (제목) | 만들 사람을 먼저 만나보세요 |
| B안 (설명) | 이력과 이수한 과정, 담당한 프로젝트가 한 페이지에 모여 있습니다. 문의 전에 상대를 알고 시작하는 쪽이 편합니다. |
| B안 (전체 보기) | 빌더 전체 보기 |

- A안 제목의 **"만든"이 아니라 "맡은"**, B안 제목의 **"만든"이 아니라 "만들"** — 앞 섹션이 과거 결과물이라면 이 섹션은 앞으로 내 프로젝트를 맡을 사람이라는 뜻이다. 시제를 바꿔 두 섹션의 역할을 분리했다.
- 기수를 언급하지 않는다(FN-P01-26 — 기수 배지는 경력이 짧다는 인상만 준다).

## 06 교육 · 조직

제목 + 설명. **수치 카운터 금지**(FN-P01-08 · POL-01).
**"교육 과정 보기" CTA를 두지 않는다** — P-07은 개발 범위 밖이고, 교육을 전면에 내세우지 않는다(회의록 260812).
교육 라인업 미수령 시 교육 부분을 숨기고 조직 부분만 남긴다(§4.6) — **그 상태에서도 문장이 성립하도록 두 안 모두 둘째 문장에 근거를 두지 않았다.**

| 구분 | 카피 |
|---|---|
| A안 (제목) | 배운 곳까지 적혀 있습니다 |
| A안 (설명) | 빌더 페이지에는 이수한 과정이 함께 나옵니다. 배운 사람이 그대로 담당자로 들어옵니다. |
| B안 (제목) | 실력의 출처가 이어집니다 |
| B안 (설명) | 사람을 가르쳐 프로젝트에 넣고 진행까지 맡깁니다. 결과물에서 담당자로, 담당자가 배운 과정까지 거슬러 올라갈 수 있습니다. |

- **"체계적인 교육" 류의 수식은 쓰지 않았다.** 교육 품질을 주장하려면 P-07이 근거로 있어야 하는데 범위 밖이다(§4.1 v3.9 주석의 안건 8 선행 조건 문제를 회피한 선택).
- A안은 "적혀 있다"는 사실만, B안은 "거슬러 올라갈 수 있다"는 경로를 말한다. 둘 다 방문자가 P-06에서 실제로 하는 동작이다.

## 07 일하는 방식

제목 + 8단계(2행 4열 · 라벨 + 설명, FN-P01-27) + P-09 이동.

| 구분 | 카피 |
|---|---|
| A안 (제목) | 여덟 단계를 미리 읽어보세요 |
| A안 (설명) | 단계 사이마다 검수보고서와 컨펌이 있습니다. 무엇이 끝났고 무엇이 남았는지 매번 문서로 받습니다. |
| A안 (이동 링크) | 8단계 자세히 보기 |
| B안 (제목) | 시작부터 끝까지 열려 있습니다 |
| B안 (설명) | 컨펌하지 않으면 다음 단계로 넘어가지 않습니다. 진행 상황을 물어봐야 알게 되는 일이 생기지 않습니다. |
| B안 (이동 링크) | 일하는 방식 전체 보기 |

### 8단계 라벨 · 설명

**라벨 8종은 발주사 지시로 확정된 값이다** (v4.2 — 1단계 「수주·채널개설」 → 「계약·소통채널 개설」). 두 안 모두 라벨을 바꾸지 않고 설명만 다르게 쓴다.

| # | 라벨 (확정 · 공통) | A안 설명 | B안 설명 |
|:---:|---|---|---|
| 1 | 계약 · 소통채널 개설 | 전용 채널이 열리고 담당 빌더가 정해집니다. | 담당 빌더가 정해지고, 이야기할 창구가 하나로 모입니다. |
| 2 | 킥오프 · 계정수급 | 요구사항을 정리하고 배포·도메인 계정을 넘겨줍니다. | 무엇을 만들지 합의한 내용이 문서로 남습니다. |
| 3 | 기획 | 화면 목록과 기능 범위를 보고 컨펌합니다. | 화면 목록과 기능 범위에 컨펌하기 전에는 다음으로 넘어가지 않습니다. |
| 4 | 디자인 | 시안을 받아 수정 의견을 보냅니다. | 시안을 보고 고칠 곳을 말할 수 있는 구간입니다. |
| 5 | 개발 | 주간 단위로 진행 상황을 받아봅니다. | 매주 어디까지 됐는지 알 수 있습니다. |
| 6 | 배포 · SEO | 실제 도메인에 올라간 화면과 검색 노출을 봅니다. | 검색에 어떻게 잡히는지까지 보고 넘어갑니다. |
| 7 | 이관 | 계정과 코드를 넘겨받고 사용법을 안내받습니다. | 계정도 코드도 고객 소유로 남습니다. |
| 8 | 종료 · 하자보수 | 검수보고서로 마무리하고 합의된 기간 동안 대응받습니다. | 끝난 뒤에도 합의된 기간 동안 연락할 곳이 있습니다. |

> **기능명세 §4.7의 단계 설명을 대체한다.** 원 표는 "…배정합니다 / …받습니다"로 **수행사가 주어**다. 이 화면의 모든 문장이 방문자 시점이므로 8단계만 공급자 시점이면 톤이 끊긴다. §4.7 주석이 이 표를 "기획-2안이며 팀원 재량 대체 가능"으로 명시하고 있다.
> 이관 정책의 대외 공개 여부(안건 9)는 미결이므로 7단계 설명에 **정책 내용을 쓰지 않고 사실만** 적었다.

## 08 문의

제목 + 설명 + CTA(C-03). 상하 여백 축소(FN-P01-36) · 코너 마크 없음(FN-P01-28).

| 구분 | 카피 |
|---|---|
| A안 (제목) | 무엇을 만들지만 알려주세요 |
| A안 (설명) | 예산이나 일정이 정해지지 않아도 됩니다. 어떤 결과물이 필요한지, 그것부터면 충분합니다. |
| B안 (제목) | 아직 정리되지 않아도 됩니다 |
| B안 (설명) | 필요한 것을 함께 정리하는 데서 시작합니다. 내용을 보고 맞는 빌더를 연결해 드립니다. |

폼 항목은 늘리지 않는다(FR-5.2). 두 안 모두 예산·일정·규모를 **묻지 않겠다고 먼저 말해** 진입 부담을 낮춘다.

| 위치 | A안 | B안 | 상태 |
|---|---|---|---|

| 문의 섹션 CTA | 프로젝트 상담하기 | 프로젝트 상담하기 | **확정값 유지 권장** |
| 문의 섹션 CTA (대안) | 프로젝트 상담하기 | 필요한 것부터 상담하기 | 후보 |
| 하단 마이크로카피 | 상담이 계약으로 이어지지는 않습니다. | 먼저 물어보고 나중에 정하셔도 됩니다. | ⚠️ **적용 철회 상태 — 아래 참조** |

### CTA 관련 제약 3건

| # | 제약 | 근거 |
|:---:|---|---|
| 1 | **P-01 CTA 문구는 「프로젝트 상담하기」로 확정**돼 있고 `utm_source=home`이 붙는다. 바꾸려면 화면설계 §4.3 · 기능명세 §3.3 · IA §5.4 **3곳을 동시에 개정**해야 한다 | C-03 |
| 2 | 3종 CTA는 **모두 "상담" 계열**로 부담 수위를 통일한다. "의뢰"처럼 계약을 전제한 동사를 쓰지 않는다 — 대안 문구도 이 규칙을 지켰다 | REQ-F-055 |
| 3 | **보조 링크·버튼을 새로 만들지 않는다.** P-01의 전환 경로는 하나뿐이다 | REQ-F-007 |

### ⚠️ 하단 마이크로카피 — 요청과 확정 사항이 충돌한다

**요청받은 항목이라 후보를 넣었으나, 현재 규격상 P-01에는 마이크로카피를 둘 수 없다.**

- `REQ-F-056`은 v3.2에서 **P-01 적용이 철회**됐고, 결정시트 `H-1`이 *"P-01은 강한 CTA 하나로만 간다"*를 확정 방침으로 못 박았다. 화면설계 v1.4도 「CTA 마이크로카피 2종 삭제」로 개정됐다.
- 다만 **화면설계 §5.1 도면의 섹션 8에는 `▫` 마이크로카피 표기가 그대로 남아 있다.** 개정이 도면에 완전히 반영되지 않은 것으로 보인다 — 문서 간 불일치로 별도 정리가 필요하다.
- 위 후보는 **`H-1`을 되집는 결정이 있을 때만** 쓸 수 있다. `H-1`은 *"저마찰 경로가 없으니 하나 넣자는 방향으로 되돌아가지 말 것"*을 명시하고 있으므로, 넣으려면 그 결정을 먼저 뒤집어야 한다.
- 마이크로카피는 **텍스트로만** 둔다. 링크·버튼으로 만들면 `REQ-F-007` 위반이다.
