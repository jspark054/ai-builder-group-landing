## 1. 지금 이 값은 아직 화면에 나가지 않는다

공개 화면이 `meta_title` · `meta_description` 컬럼을 **읽지 않는다.**

| 화면 | 현재 메타 출처 |
|---|---|
| P-13 인사이트 상세 | **컬럼 사용** |
| P-04 프로젝트 상세 | `project.title` + 카피 파일 접미사 · description 은 `summary` |
| P-06 빌더 상세 | `builder.display_name` + 카피 파일 접미사 |

**순서**

```
① 초안 확정  →  ② P-04 · P-06 이 컬럼을 읽도록 수정  →  ③ DB 입력
```

②가 devlog 미결의 「P-04 meta description POL-06 하한 미달」을 함께 닫는다 —
지금은 44~50자짜리 `summary` 를 description 으로 쓰고 있다.

**②의 구현 규칙 (지시 3)** — `meta_title` 은 **접미사를 포함한 완성된 제목**이다.
화면이 뒤에 무엇을 덧붙이지 않는다. 값이 없을 때만 지금의 「제목 + 접미사」로 떨어진다.

## 2. 작성 규칙

- **POL-06** — `meta_title` 40자 이내 · 핵심 키워드를 앞 15자 이내 ·
  `meta_description` 80~110자. **아래 길이는 전부 실측값이다**
- **화면에 없는 사실을 만들지 않았다.** 전부 기존 `summary` · `body_what` · `bio` ·
  `career` 에서 끌어왔다. 수치 · 성과 · 고객 평가를 새로 만들지 않았다 (POL-01 · POL-09)
- 프로젝트는 **무엇을 만들었는지가 앞에**, 빌더는 **표기명이 첫 단어**다

⚠ 한글 문자 수 기준이다. 검색 결과에서 잘리는 실제 기준은 픽셀 폭(약 600px)이라
POL-06 자신이 밝힌 대로 근사값이다.

**빌더 6명은 전원 가상 인물(예행 샘플)이다.** 실빌더 전환 시 이 문안은 전부 폐기된다.

실빌더 전환 때 본인 확인과 함께 정리한다 (지시 1).
